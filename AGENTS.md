# Codex Agent Instructions

Read `OPENAI_ACCOUNT_HANDOVER.md`, `HANDOFF.md`, and `README.md` before changing this repository.

This repository is the Jekyll source for the Hebrew democracy summaries site. Do not manually edit generated HTML, `_site/`, or `pagefind/`. Shared layout changes belong in `_layouts/`, `_includes/`, `_data/site.json`, and `assets/css/site.css`.

For paper additions:

- Read the private `demokratia-info/democracy-paper-suggestions-private` `Authors.csv` before checking suggestions, consuming the public queue, or searching. Prioritize relevant non-duplicate papers by authors marked `high`, `normal`, or `low`, but do not add out-of-scope papers only because the author is listed. Never select, add, summarize, or queue a paper when any source author is marked `blocked`.
- Private `Authors.csv` includes `Current Site Papers`, the count of current public `_papers/*.md` records whose `sourceAuthors` or `authors` include that author. During the 00:05 paper-addition phase, refresh this column after all public paper additions/removals and author metadata edits by running `python3 scripts/update_author_site_counts.py /path/to/private/Authors.csv`, then commit/push the private update separately.
- Run `scripts/check_private_repo_access.sh` before private suggestion or author-policy work. If it fails after retries, stop before consuming public queue rows and report the exact access blocker.
- The private repository also contains `page_feedback_queue.csv` for visitor correction/comment submissions and optional suggested paper photos. Act only on rows that the editor marked `approved_for_update`; verify corrections against the paper/source before changing a public page, validate any approved suggested photo before using it, and never expose visitor email, phone, IP hash, original uploaded photos, or private editor notes in public files or reports.
- Use `_data/paper_index.json` as the primary duplicate and ordering index.
- Nightly updates should review at most the first pending row from the private `demokratia-info/democracy-paper-suggestions-private` `suggest_queue.csv`, first come first served. Accept it only if it fits the site's subject criteria and liberal-democratic spirit and is not a duplicate. Remove the processed suggestion row from the private queue whether accepted or rejected, and do not expose submitter name, email, or IP hash in public files or reports.
- Nightly updates should then consume enough rows from `paper_queue.csv` to reach the normal 10-paper nightly batch. Remove those rows only after adding the papers, and rebuild a fresh 100-paper queue only when the queue has fewer rows than needed at the start.
- Treat private `Authors.csv` rows with priority `blocked` as hard exclusions for visitor suggestions, existing `paper_queue.csv` rows, and newly discovered queue candidates. If a blocked author appears in a private suggestion, reject and remove that suggestion row. If a blocked author appears in the public queue, remove that queue row and continue to the next candidate without counting it toward the nightly batch.
- Add one source file per paper under `_papers/`.
- Use existing topic IDs from `_data/topics.json` unless a durable new topic is really needed.
- Do not add generic source-reading sections such as `מה כדאי לבדוק במאמר המקורי?`, `מה חשוב לבדוק במקור עצמו?`, or `איך כדאי לקרוא את המקור?` unless the guidance is concrete and tied to that paper's actual method, sources, cases, definitions, period, or evidence. Omit the section when the only available text would be boilerplate. Likewise, do not repeat body paragraphs that merely restate metadata already shown near the title, such as `רשומת המקור מציינת...` or `המקור פורסם...`, and avoid filler sections such as `מה נושא המאמר?`, `האם המאמר משפטי או פוליטי?`, `המסגור הזה נשען על כותרת המקור...`, `כדי לשמור על נאמנות למקור...`, or `השורה התחתונה צריכה להיקרא...`.
- Add a newly sourced or generated 800x600 landscape JPEG for every new paper and keep `image_catalog.json` current. Never reuse an existing site image for a new paper. Every paper `image` object must include `fitness`, one of `high`, `standard`, or `low`, for that image-paper tuple. Mark `high` only when the image is clearly and specifically matched to the paper; approved user-uploaded replacements are always `high`. New paper images should follow the older warm editorial illustration style with people, institutions, documents, civic rooms, public spaces, depth, and texture; avoid flat vector icons, isolated scales/buildings, abstract blobs, sparse diagrams, and other schematic graphics.
- During the 00:05 paper-addition heartbeat, refresh `_data/homepage_high_fit_sample.json` by running `python3 scripts/sample_homepage_high_fit.py --write`. The homepage sample must contain six papers whose `image.fitness` is `high`.
- Keep `paper_queue.csv` in CSV format with `paper_name,authors,doi,topic` columns. The `topic` value should use existing topic IDs.
- Keep the public `suggest_queue.csv` as a header-only placeholder. Keep the real private suggestion queue in CSV format with `submitted_date,submitted_at,paper_name,doi,submitter_name,submitter_email,submitter_ip_hash,status,notes` columns. Keep private `page_feedback_queue.csv` in CSV format with `submitted_date,submitted_at,page_url,page_title,page_slug,paper_title,doi,comment,submitter_email,submitter_phone,submitter_ip_hash,status,editor_notes,applied_at,suggested_photo_path,suggested_photo_name,suggested_photo_type,suggested_photo_size,suggested_photo_width,suggested_photo_height,submitter_role` columns. It may contain visitor duplicates; do not let a duplicate suggestion or comment block the build.
- Bump `_data/site.json` `lastUpdated` and `cacheVersion` on each successful content update so returning browsers refresh stale HTML/CSS/Pagefind assets.
- Keep each new paper's `datePublished` equal to its site creation date and do not change it later; use `dateModified`/`lastUpdatedHe` for later edits. The red `חדש!` badge is based on `datePublished` and `_data/site.json` `newBadgeDays`.
- For every new paper, make a serious pass at author profile links before leaving author names unlinked. Reuse matching URLs already present in `_papers/*.md`, then check DOI/publisher metadata, ORCID links, official institutional directories, clearly maintained academic personal sites, and quoted-name searches with the affiliation or paper title. Add only certain profile links to `authorsHtml`, `authors`, and `sourceAuthors`; report unresolved names rather than guessing.
- New summaries should follow the admin GEO brief: deeper democratic-liberal analysis, verified numbers only, 2-3 short translated quotes when source text supports them, and at least 10 FAQ-style question/answer sections.
- Regenerate the compact index with `python3 scripts/validate_sources.py --write-index`.
- Validate with `python3 scripts/validate_sources.py` before committing; this also checks the paper queue for duplicate DOI/title and invalid topic IDs, and checks the public suggestion queue placeholder structure.

For publishing, stage only intentional changes, commit with a clear message, push `main`, and monitor the GitHub Pages workflow. `todo.md` is tracked and should be committed when it changes.
